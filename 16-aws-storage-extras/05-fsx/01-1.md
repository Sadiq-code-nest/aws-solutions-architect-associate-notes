# 1

This is one of the **most confusing SAA-C03 topics** because AWS has **four different FSx services**.

**Don't memorize them.**

Instead, remember one rule:

> **FSx = AWS runs someone else's file system for you.**
> 

Normally AWS has its own storage services:

- S3 → Object Storage
- EBS → Block Storage
- EFS → Linux File Storage

But many companies already use **Windows File Server, NetApp, Lustre, OpenZFS** in their own data centers.

AWS says:

> "Don't change your application. We'll run the same file system for you."
> 

That's exactly what **Amazon FSx** is.

---

# PART 1 — What is Amazon FSx?

## Simple Definition

Amazon FSx is

> **A fully managed service that provides popular third-party file systems on AWS.**
> 

Think of it like this.

Instead of AWS inventing a new file system,

they host existing file systems.

---

## Real Life Analogy

Imagine AWS is a hotel.

Customers come from different countries.

Some speak

- English
- Japanese
- Arabic
- French

Instead of asking everyone to learn English,

the hotel hires translators.

AWS does the same.

Instead of forcing everyone to use EFS,

AWS supports

- Windows File Server
- Lustre
- NetApp
- OpenZFS

# Scratch vs Persistent

This confuses everyone.

---

## Scratch File System

Think

Temporary Workspace.

Example

Video editing.

After editing

Workspace deleted.

No problem.

---

Characteristics

- Temporary
- No replication
- If file server dies

↓

Data lost

- Very fast
- Cheaper

---

Diagram

```
Video Processing

↓

Scratch

↓

Delete
```

---

## Persistent File System

Think

Important Business Data.

Need reliability.

AWS replicates data

within the same AZ.

If server fails

AWS rebuilds automatically.

---

Diagram

```
Financial Data

↓

Persistent

↓

Server Failure

↓

AWS Restores
```

---

# Comparison

| Scratch | Persistent |
| --- | --- |
| Temporary | Long-term |
| Cheapest | More expensive |
| No replication | Replicated |
| Data loss possible | Data protected |
| HPC temporary jobs | Production workloads |
