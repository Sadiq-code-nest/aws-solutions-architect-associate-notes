# AWS Storage Gateway — Complete SAA-C03 Notes (Crystal Clear)

This is one of the most confusing AWS Storage topics because it combines **on-premises storage** with **AWS storage**.

The trick is:

> **Storage Gateway = A bridge between your local data center and AWS Storage.**
> 

Don't memorize the four gateway types. First understand **why Storage Gateway exists**.

---

# Part 1 — Why Do We Need Storage Gateway?

Imagine your company already has a data center.

```
          Company Data Center

      ┌──────────────────────┐
      │                      │
      │ Servers              │
      │ Databases            │
      │ Applications         │
      │ Local Storage        │
      │                      │
      └──────────────────────┘
```

Now the company wants to use AWS.

Problem:

- They can't move everything overnight.
- Applications still need local storage.
- Backups should go to AWS.
- Files should be shared with AWS.

---

## Without Storage Gateway

```
Server

↓

Local Disk
```

Everything stays on-premises.

No cloud integration.

---

## With Storage Gateway

```
          On-Premises

 Server

     │

     ▼

Storage Gateway

     │

────────Internet────────

     │

     ▼

AWS

S3 / FSx / EBS / Glacier
```

Storage Gateway is simply

> **A translator between your local servers and AWS Storage.**
>

# PART 2 — S3 File Gateway

This is the easiest one.

---

## Problem

Your Windows/Linux servers expect

Shared folders.

AWS S3

is NOT a file system.

It stores

Objects.

Applications cannot simply mount S3.

---

AWS Solution

File Gateway.

---

# How It Works

```
        Application

             │

     SMB / NFS

             │

             ▼

      S3 File Gateway

             │

       Converts Files

             │

             ▼

          Amazon S3
```

Applications think

they're writing files.

Actually

Storage Gateway stores

Objects

inside S3.

---

Actually

Storage Gateway uploads


Amazon S3.
