# Ans3

This is a **classic NACL + Security Group + ephemeral port** question. The most important thing is to understand why **option 1 is NOT actually correct**, even though it may look reasonable.

## 1. ✅ Correct Answers

The correct TWO are:

### ✅ 2. Security Group — allow inbound TCP 443 from `0.0.0.0/0`

### ✅ 5. Network ACL — allow:

- **Inbound TCP 443** from `0.0.0.0/0`
- **Outbound TCP 32768–65535** to `0.0.0.0/0`

So:

```
Internet
   │
   │ TCP destination port 443
   ▼
┌─────────────────┐
│      NACL       │
│ IN: 443   ✅    │
│ OUT: Ephemeral ✅│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Security Group  │
│ IN: 443    ✅   │
└────────┬────────┘
         │
         ▼
       EC2
     Port 443
```

---

# 2. 🧠 Core Concept — Very Simple

The question is really testing:

> **"How do I allow HTTPS through BOTH a stateful Security Group and a stateless NACL?"**
> 

Remember:

### Security Group = **Stateful**

If it allows:

```
Internet → EC2:443
```

the return traffic is automatically allowed.

### NACL = **Stateless**

You must explicitly allow **both directions**.

And here's the tricky part:

The return traffic does **NOT** use port 443 as its destination.

---

# 3. 🔥 Understand the Traffic Flow

Suppose your browser chooses ephemeral port `50000`.

### Request

```
Client
Source:      50000
Destination: 443
       │
       ▼
      EC2
```

So inbound NACL needs:

```
INBOUND
TCP
Port 443
Source 0.0.0.0/0
```

✅

---

### Response

The EC2 server responds from port 443:

```
EC2
Source:      443
Destination: 50000
       │
       ▼
Client
```

Notice:

```
Source port      = 443
Destination port = 50000
```

Therefore the NACL needs to allow:

```
OUTBOUND
TCP
Port 32768–65535
Destination 0.0.0.0/0
```

✅

That's why **option 5** is correct.

---

# 4. 🧠 Why Security Group Needs Only Port 443

Security Groups are **stateful**.

You add:

```
Inbound:
TCP 443
Source: 0.0.0.0/0
```

Then:

```
Internet
   │
   │ 50000 → 443
   ▼
 EC2
   │
   │ 443 → 50000
   ▼
Internet
```

The SG automatically understands that the response belongs to an established connection.

So you **don't need** an outbound ephemeral-port SG rule.

---

# 5. ❌ Why Every Other Option Is Wrong

## ❌ Option 1

> NACL allows both inbound and outbound TCP port **443**
> 

This is the big trap.

It says:

```
NACL:
IN 443 ✅
OUT 443 ❌
```

But the response is:

```
443 → 50000
```

The destination port is **50000**, not 443.

Therefore:

```
Outbound destination port 443
             ❌
doesn't match
destination port 50000
```

So the response gets blocked.

### Very important:

> **NACL return traffic uses the client's ephemeral port, not the server's port 443.**
> 

---

## ❌ Option 3

> NACL outbound `32768–65535`
> 

This handles the **return traffic**, but it doesn't allow the initial HTTPS request.

You would have:

```
INBOUND 443 ❌
OUTBOUND ephemeral ✅
```

The request can't even reach the EC2 instance.

---

## ❌ Option 4

> Security Group allows TCP 443 to destination `0.0.0.0/0`
> 

This is conceptually wrong for an **inbound SG rule**.

For inbound traffic, you specify the **source**:

```
Inbound SG:
TCP 443
Source: 0.0.0.0/0
```

Not:

```
Destination: 0.0.0.0/0
```

---

# 6. 🎯 The Critical Difference: SG vs NACL

|  | Security Group | Network ACL |
| --- | --- | --- |
| Stateful? | ✅ Yes | ❌ No |
| Applied to | ENI/instance | Subnet |
| Return traffic | Automatically allowed | Must explicitly allow |
| HTTPS inbound | Allow 443 | Allow 443 |
| HTTPS response | Automatically allowed | Allow ephemeral ports |
| Rules | Allow only | Allow + Deny |
| Rule order | Not like NACL numbered processing | Lowest-number rule first |

### Memory trick

> **SG remembers. NACL doesn't.**
> 

Therefore:

```
SG:
443 inbound → response automatically ✅

NACL:
443 inbound → response rule required ✅
```

---

# 7. 🏢 Real-World Example

Imagine a hotel receptionist.

You call the hotel from room/client port `50000`:

```
You
Port 50000
   │
   │ "Connect me to HTTPS"
   ▼
Hotel
Port 443
```

The hotel responds:

```
Hotel
Port 443
   │
   │ Response → your port 50000
   ▼
You
Port 50000
```

The NACL needs to allow both:

```
IN:
443

OUT:
32768–65535
```

It doesn't mean:

```
IN 443
OUT 443
```

because **443 is the server's port, not the client's return destination port.**

# 8. 🔑 Exam Keywords

| Clue | Think |
| --- | --- |
| **Network ACL** | Stateless |
| **Security Group** | Stateful |
| **port 443** | HTTPS |
| **any source** | `0.0.0.0/0` |
| **return traffic** | Ephemeral port |
| **32768–65535** | Ephemeral ports |
| **NACL blocks all traffic** | Need explicit inbound + outbound rules |
| **Default SG** | Stateful; inbound must still be explicitly allowed |

# 9. 🧠 Short Memory Trick

### For HTTPS through NACL:

```
IN  → 443
OUT → Ephemeral
```

And:

> **"Server listens on 443; client listens on an ephemeral port."**
> 

That's the key to this entire question.

---

# 10. 📝 SAA-C03 Exam Takeaway

> **Because NACLs are stateless, HTTPS requires inbound TCP 443 plus outbound ephemeral ports for return traffic, while a stateful Security Group only needs the inbound 443 rule.**
>
