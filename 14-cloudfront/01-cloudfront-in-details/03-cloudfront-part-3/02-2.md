# 37. CloudFront vs ALB

This is a common exam confusion.

| CloudFront | ALB |
| --- | --- |
| Global edge service | Regional load balancer |
| Global distribution | Distributes among targets |
| Caching | No CDN caching role |
| WAF integration | WAF can also associate directly |
| TLS at edge | TLS termination |
| Edge functions | No |
| DDoS resilience | Not its primary role |
| Routes to origins | Routes to target groups |
| Global front door | Application traffic distribution |

Think:

```
CloudFront
"Where should traffic enter globally?"

ALB
"Which application server should receive it?"
```

# 43. CloudFront vs Security Group

```

→ Instance/resource network access
→ Stateful
→ Allow rules
→ No explicit deny

```

```
→ HTTP/HTTPS request inspection
```

>

**WAF**

not:

**Security Group**

# 44. CloudFront vs NACL

NACL:

```
Subnet-level
Stateless
ALLOW + DENY
IP/port/protocol
```

WAF:

```
Application/web layer
HTTP/HTTPS
Rate rules
SQL injection
XSS
headers
URI
IP
etc.
```

So:

> "Block HTTP flood based on request rate"
> 

→ **WAF**

> "Explicitly deny an IP at subnet/network level"
> 

→ **NACL**

# 45. CloudFront vs VPC Flow Logs

VPC Flow Logs:

```
Observe network traffic metadata
        ↓
Logs
        ↓
Analysis
```

CloudFront/WAF:

```
Request arrives
        ↓
Inspect/filter
        ↓
Allow or block
```

Therefore:

> **Flow Logs = visibility**
> 

> **WAF = web traffic control**
> 

Don't confuse monitoring with mitigation.


And the **five verbs** to associate with CloudFront:

> **Reach → Protect → Accelerate → Control → Deliver**
> 

### Reach

Global edge network.

### Protect

WAF + Shield + OAC + signed access.

### Accelerate

Bring users closer to AWS's edge network and reduce origin round trips where applicable.

### Control

Geo restrictions, behaviors, headers, redirects, edge functions, origin selection.

### Deliver

Static **and dynamic** content to users.

## 🧠 The ultimate exam trap

When you see:

> **"CloudFront"**
> 

don't immediately ask:

> ❌ "What are we caching?"
> 

First ask:

> **"Why does this application need a global edge layer?"**
> 

Then identify the requirement:

```
Global users / lower latency
        → CloudFront

Reduce origin load
        → CloudFront caching

DDoS
        → CloudFront + Shield

HTTP attack / rate limiting
        → CloudFront + WAF

Private S3
        → CloudFront + OAC

Temporary private content
        → Signed URL/Cookie

Edge request manipulation
        → CloudFront Functions / Lambda@Edge

Multiple origins / path routing
        → CloudFront behaviors

Primary/secondary origin
        → CloudFront origin failover

Static + dynamic application
        → CloudFront can handle BOTH
```

### One sentence to permanently fix your misconception:

> **CloudFront is not "the AWS service for caching." CloudFront is the global edge layer; caching is just one of the things that global edge layer can do.**
> 

That distinction will eliminate a **lot** of SAA-C03 CloudFront traps.
