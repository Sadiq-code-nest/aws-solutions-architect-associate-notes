# 21. Cognito User Pool Groups

User Pools can organize users into groups.

Example:

```
Application
   |
 Cognito User Pool
   |
   +-- Admins
   +-- Premium Users
   +-- Free Users
```

Groups can be useful for assigning different IAM roles/permissions through Identity Pools.

Example:

| Group | Access |
| --- | --- |
| Free Users | Basic application functionality |
| Premium Users | Premium resources |
| Admins | Administrative functionality |

# 22. Cognito Triggers

Cognito can invoke **AWS Lambda functions** during certain user-pool events.

This allows customization of authentication and registration workflows.

Examples:

- Validate user information
- Customize signup behavior
- Add custom claims
- Trigger actions after registration
- Customize authentication workflows

Think:

> **Cognito authentication event → Lambda**
>

# 24. Cognito Tokens — Exam View

| --- | --- |

| **Access token** | Authorization to protected resources/APIs |
| **Refresh token** | Obtain new tokens |

Cognito commonly uses **JWTs (JSON Web Tokens)**.

Conceptually:

```
Login
  ↓
Cognito
  ↓
JWT tokens
  ↓
Application/API
```

# 🔥 The Ultimate Exam Memory Trick

Whenever you see **Cognito**, immediately ask:

### Question 1:

**"Does the question need users to SIGN UP / SIGN IN?"**

➡️ **Cognito User Pool**

### Question 2:

**"Does the authenticated user need temporary AWS credentials to access S3/DynamoDB/etc.?"**

➡️ **Cognito Identity Pool**

### Question 3:

**"Does the application API need authenticated users?"**

➡️ **User Pool + API Gateway authorizer**

### Question 4:

**"Users want Google/Apple/corporate SAML login?"**

➡️ **User Pool federation**
