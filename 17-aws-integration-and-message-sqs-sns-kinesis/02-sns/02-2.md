# SNS vs SQS

The biggest exam question.

| SNS | SQS |
| --- | --- |
| Push | Pull |
| Publisher sends to many | Producer sends to one queue |
| Pub/Sub | Queue |
| Multiple subscribers | Usually one processing pipeline |
| Fan-out | Buffer |
| Doesn't store long-term processing queues | Stores until processed |
| Sends immediately | Consumer polls |
| One message → many copies | One message → one consumer (normally) |

# SNS + SQS Together (Most Common Architecture)

This is everywhere in AWS.

```
                 Order Service

                       │

               Publish Event

                       ▼

                Amazon SNS Topic

────────────────────────────────────────

        │             │            │

        ▼             ▼            ▼

     SQS Queue     SQS Queue    Lambda

        │             │

        ▼             ▼

 Shipping Worker   Billing Worker
```

Why?

Each service gets

its own queue.

If Shipping is slow,

Billing continues.

No interference.

# SQS vs SNS Memory Trick

Imagine **Amazon receives a new order.**

### If you use **SQS** (Queue)

```
Order

↓

Queue

↓

One worker processes it
```

Like a **single line at a bank**—each customer is served once by one cashier.

---

### If you use **SNS** (Pub/Sub)

```
Order

↓

Announcement

↓

Everyone hears it
```

Like the **airport announcement system**:

> "Flight BG101 is boarding."
> 

Passengers hear it.

Staff hear it.

Security hears it.

Display screens update.

Everyone receives the same announcement simultaneously.

# 🎯 Final Exam Cheat Sheet

| Need | Use |
| --- | --- |
| One message processed once by workers | **SQS** |
| One event notifies many systems | **SNS** |
| Decouple producers and consumers with buffering | **SQS** |
| Fan-out to multiple applications | **SNS** |
| CloudWatch alarm → Email/SMS | **SNS** |
| S3 upload → Multiple services | **SNS** |
| Traffic spikes and background processing | **SQS** |
| SNS + independent processing for each subscriber | **SNS → SQS Fan-Out** |

## One Sentence to Remember

- **SQS = "Hold this message until one worker processes it."**
- **SNS = "Broadcast this event to everyone who subscribed."**

That single distinction solves the majority of SNS vs. SQS questions on the SAA-C03 exam.
