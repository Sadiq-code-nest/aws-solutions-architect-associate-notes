# 1

This is one of the **most important AWS SAA-C03 topics**. Almost every AWS architect uses **SNS with SQS, Lambda, Email, SMS, EventBridge, CloudWatch, S3**, etc.

The biggest confusion students have is:

> **"SQS also sends messages... SNS also sends messages... what's the difference?"**
> 

Let's build the concept from scratch.

---

# Step 1: Why do we need SNS?

Imagine you own an **Amazon-like shopping website**.

A customer places an order.

Now what should happen?

```
Customer places order

↓

Many things must happen

1. Send confirmation Email
2. Send SMS
3. Update Inventory
4. Notify Shipping
5. Notify Accounting
6. Create Invoice
7. Send Analytics Event
```

Question:

Should the Order Service call all these services one by one?

```
Order Service

 ├── Email Service
 ├── SMS Service
 ├── Shipping Service
 ├── Inventory Service
 ├── Accounting Service
 ├── Analytics Service
```

### Problems

- Very slow
- If Email fails, Order may fail
- If Shipping is down, everything waits
- Order Service becomes tightly coupled

---

AWS Solution

Use SNS.

---

# Step 2: What is SNS?

SNS

=

Simple Notification Service

It is a

> **Pub/Sub (Publisher/Subscriber) messaging service.**
> 

Instead of sending messages directly,

the producer sends

ONE

message

to SNS.

SNS copies that message

to everyone interested.

---

# Restaurant Analogy

Imagine

Restaurant Manager

announces

```
"Order #105 is Ready!"
```

Everyone listening hears it.

```
Restaurant Manager

        │

        ▼

     Microphone

        │

────────┼────────

        │

Chef

Waiter

Cashier

Cleaner

Display Screen
```

The manager speaks once.

Everyone hears it.

SNS works exactly like this.

---

# SNS Architecture

```
                  Publisher

                      │

          Publish ONE Message

                      │

                      ▼

              Amazon SNS Topic

          ─────────────────────

           │      │      │

           ▼      ▼      ▼

         Email   Lambda   SQS

                  │

                SMS

                  │

               HTTP API
```

Notice

Publisher

only sends

ONE message.

SNS duplicates it.

# What is Pub/Sub?

Pub

=

Publisher

Sub

=

Subscriber

---

Imagine YouTube.

You upload one video.

```
You

↓

Upload Video
```

Subscribers

```
Person A

Person B

Person C

Person D
```

Everyone receives notification.

Exactly

SNS.

---

Publisher

doesn't know

who subscribers are.

Subscribers simply say

> "Notify me."
>

# Components of SNS

There are only two major parts.

## 1. Topic

Think of

Topic

as

a WhatsApp Group.

Example

```
Topic

OrderPlaced
```

Whenever

someone publishes

to

OrderPlaced,

everyone inside gets notified.

---

Example

```
SNS Topic

OrderPlaced
```

Subscribers

```
Email

Shipping

Lambda

Inventory

Analytics
```

---

# 2. Subscriber

Subscriber

=

Someone interested in receiving notifications.

Could be

- Email
- SMS
- Lambda
- SQS
- HTTP Endpoint
- HTTPS Endpoint
- Mobile Push Notification

---

Example

```
SNS Topic

↓

Email

↓

admin@company.com
```

Every message becomes email.

# How SNS Works

Suppose

Customer places order.

---

Step 1

```
Customer

↓

Order Service
```

---

Step 2

Order Service publishes

ONE message.

```
{
 "OrderID":1001,
 "Customer":"John"
}
```

to

SNS Topic.

---

Step 3

SNS copies

that message.

```
SNS

↓

Copy

↓

Email

↓

Copy

↓

Shipping

↓

Copy

↓

Inventory

↓

Copy

↓

Analytics
```

Nobody shares.

Everyone gets

their own copy.

# Important

SNS

does NOT

wait.

# Why SNS is Fast

Without SNS

```
Order Service

↓

Email

↓

SMS

↓

Inventory

↓

Shipping

↓

Analytics
```

One by one.

Slow.

---

With SNS

```

↓

SNS

↓

Email

SMS

Shipping

Inventory

Analytics
```

Everything happens simultaneously.

# Fan-Out Pattern

Very famous exam topic.

SNS

copies

ONE message

to MANY destinations.

Called

Fan-Out.

Diagram

```
             SNS

              │

──────────────┼─────────────

│             │            │

Email       Lambda       SQS

│             │            │

SMS        Database     Worker
```

One message

becomes many.
