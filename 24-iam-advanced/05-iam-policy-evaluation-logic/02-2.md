# 2

This is probably the **most confusing IAM topic** in AWS SAA-C03. Once you understand the **evaluation flow**, almost every IAM question becomes easy.

The easiest way to remember it is:

> **AWS checks every security layer one by one. If any layer explicitly says DENY, the request immediately fails.**
> 

---

# AWS IAM Policy Evaluation Logic

Imagine a user wants to perform this action:

```
Action:
Delete an S3 Bucket
```

AWS doesn't immediately allow it.

Instead, AWS asks several questions.

```
                 User Request
                     │
                     ▼
          1. Explicit DENY?
                     │
         Yes ─────────────► DENY
                     │ No
                     ▼
        2. Organizations SCP
                     │
                     ▼
      3. Resource-Based Policy
                     │
                     ▼
      4. Identity-Based Policy
                     │
                     ▼
      5. Permission Boundary
                     │
                     ▼
         6. Session Policy
                     │
                     ▼
             Final Decision
```

Think of it as **passing through multiple security gates**.

# Step 1 — Explicit Deny (Highest Priority)

AWS always checks for e**xplicit deny** first.

If there is even one explicit deny...

Everything stops.

Example:

IAM Policy

```json
{
 "Effect":"Deny",
 "Action":"s3:DeleteBucket"
}
```

User also has

```json
Allow
s3:*
```

Result?

```
DENY
```

Because

```
Explicit Deny

beats

Allow
```

# Complete Example 4 (Cross-Account S3 Upload)

**Scenario:**

- **Account A:** User Alice.
- **Account B:** S3 bucket `company-backups`.

Policies:

- Alice's IAM policy:

```
Allow
s3:PutObject
```

- Bucket policy:

```
Allow
Alice from Account A
```

Flow:

```
Alice Uploads File
        │
        ▼
Explicit Deny? → No
        │
        ▼
SCP? → Allows
        │
        ▼
Bucket Policy? → Allows Alice
        │
        ▼
IAM Policy? → Allows PutObject
        │
        ▼
Boundary? → Allows S3
        │
        ▼
Session Policy? → No restriction
        │
        ▼

```

Now change only one thing:

Bucket policy removes Alice.

Everything else still allows.

Result:

```
Bucket Policy

↓

No Allow

↓

❌ Upload Fails
```

Because the resource itself no longer trusts her.

# SAA-C03 Exam Rules

| If the question says... | Answer |
| --- | --- |
| Restrict an entire AWS account | **SCP** |
| Restrict one IAM user or role | **Permission Boundary** |
| Grant permissions to a user | **IAM Policy** |
| Allow cross-account access to an S3 bucket | **Resource-Based Policy (Bucket Policy)** |
| Temporary credentials with additional restrictions | **Session Policy** |
| Any explicit deny exists anywhere | **Access is denied immediately** |

## Final Golden Rule

For an action to succeed:

- ❌ There must be **no explicit deny**.
- ✅ Every applicable limiting layer (SCP, Permission Boundary, Session Policy) must allow it.
- ✅ The required permissions must be granted by the relevant identity-based policy and/or resource-based policy (depending on the service and access pattern).

A simple way to remember it is:

> **One explicit deny = game over. Otherwise, every required "gate" must allow the request.**
>
