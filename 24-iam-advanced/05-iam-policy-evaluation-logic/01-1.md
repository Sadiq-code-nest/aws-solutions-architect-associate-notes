# IAM Permission Boundaries (SAA-C03 Complete Understanding)

This is an **advanced IAM topic**, but once you understand the idea, it's actually simple.

The easiest way to remember it is:

> **Permission Boundary = Maximum permission a specific IAM User or Role can ever have.**
> 

Think of it as **putting a ceiling on someone's permissions**.

---

# Why Do We Need Permission Boundaries?

Imagine you're the AWS administrator.

You hire a junior DevOps engineer.

You want them to:

- Create IAM users ✅
- Create EC2 instances ✅
- Create S3 buckets ✅

But you **never** want them to become an administrator.

How do you stop them?

This is where **Permission Boundaries** help.

---

# Think of it Like a Cage

Imagine a dog inside a fence.

```
           Fence
+-------------------------+
|                         |
|      🐶 Dog             |
|                         |
+-------------------------+
```

The dog can run anywhere **inside** the fence.

But it **can never leave** the fence.

Permission Boundary works exactly like that.

The user can only receive permissions **inside the boundary**.

---

# What is a Permission Boundary?

A Permission Boundary is simply an **IAM Managed Policy**.

But instead of granting permissions,

it defines the **maximum permissions** that the user or role can ever receive.

Think:

```
Normal IAM Policy
        =
What the user IS ALLOWED to do

Permission Boundary
        =
Maximum the user CAN EVER BE ALLOWED to do
```

---

# How Permission Evaluation Works

Both must allow the action.

```
          IAM Policy
              │
              │
              ▼
        Permission Boundary
              │
              ▼
          Final Permission
```

If either one says **No**, access is denied.

---

# Why Not Just Use IAM Policies?

Because users can sometimes create new users or attach new policies.

Without boundaries:

```
Developer

↓

Creates New IAM User

↓

Attaches AdministratorAccess

↓

Now becomes Admin
```

Dangerous.

With Permission Boundary:

```
Developer

↓

Creates New User

↓

Boundary applied

↓

Maximum permissions limited

↓

Cannot become Admin
```

---

# Supported For

Permission Boundaries work on:

✅ IAM Users

✅ IAM Roles

Not supported for:

❌ IAM Groups

---

# Permission Boundary vs IAM Policy

This is where students get confused.

## IAM Policy

Answers:

> **"What permissions does this user currently have?"**
> 

Example:

```
Allow:

EC2

S3
```

---

## Permission Boundary

Answers:

> **"What is the maximum permission this user can ever have?"**
> 

Example:

```
Maximum:

EC2

S3

Lambda
```

Even if someone later attaches:

```
AdministratorAccess
```

Boundary blocks everything outside it.

---

# Permission Boundary vs SCP

This is another favourite exam comparison.

## Permission Boundary

Works on:

```
One User

or

One Role
```

---

## SCP

Works on:

```
Entire AWS Account

or

Entire Organizational Unit (OU)
```

---

### Visual

```

--------------------------
```

SCP controls the **account**.

Permission boundary controls **individual users or roles**.

# Comparison Table

| Feature | Permission Boundary | SCP |
| --- | --- | --- |
| Scope | IAM User / IAM Role | AWS Account / OU |
| Grants permissions? | ❌ No | ❌ No |
| Limits permissions? | ✅ Yes | ✅ Yes |
| Requires IAM policy too? | ✅ Yes | ✅ Yes |
| Works in Organizations? | No | Yes |
| Used for | Individual users or roles | Entire accounts |

# Permission Evaluation Logic

AWS evaluates permissions like this:

```
                Request

                   │

                   ▼

           IAM Policy

                   │

           Is it Allowed?

                   │

                  YES

                   │

                   ▼

      Permission Boundary

                   │

           Is it Allowed?

                   │

              YES

                   │

                   ▼

             Access Granted
```

If either says **No**:

```
Access Denied
```

# Real-Life Analogy

Imagine a child receives pocket money.

- **Parents' rule (Permission Boundary):** "You can spend at most £50."
- **Today's allowance (IAM Policy):** "You have £20 today."

The child **cannot spend £100**, even if someone tries to give them more, because the parents' rule is the maximum limit.

Similarly:

- **IAM Policy** = current permissions.
- **Permission Boundary** = maximum allowed permissions.

# SAA-C03 Exam Tips

If the question says:

- **"Limit the maximum permissions of a specific IAM user or role"** → ✅ **Permission Boundary**
- **"Restrict all accounts in an AWS Organization"** → ✅ **SCP**
- **"Grant permissions to a user"** → ✅ **IAM Policy**
- **"Prevent developers from escalating their own IAM permissions"** → ✅ **Permission Boundary**

### One-Line Exam Summary

**IAM Permission Boundaries set the maximum permissions that an IAM user or role can receive. They do not grant permissions by themselves; the action must also be allowed by the attached IAM policies.**
